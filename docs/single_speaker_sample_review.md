# 短片段多人检测结果复核

依据用户提供的 1.jsonl 和六个 FLAC 文件。人工依据是用户盲听反馈“大部分只有一个人”；
没有将六个样本逐个标为经过验证的单人真值，也没有仅凭时长统计替代听辨。

## 结果文件

1.jsonl 有 4,454 行 result，全部 status=ok，没有 header：

- 4,452 条有两个模型说话人标签，2 条有三个标签。
- 3,539 条音频不足 3 秒（79.5%），时长中位数 2.04 秒。
- 3,048 条的第二大说话人累计时长不足 0.5 秒（68.4%）。
- 2,771 条中，最大说话人时长等于全部语音的并集时长（62.2%）；
  这表示模型把其他标签全部标在与主标签重叠的时间内。

这个文件只含模型多标签记录，是结果子集，不能据此计算全库多人率或误判率。
累计说话人时长之和可超过音频时长，因为模型允许重叠说话，并非必然是求和代码错误。

## 新策略对这个子集的影响

保守策略默认阈值：每人 0.5 秒、每人 10% 语音占比、总语音 3 秒，
至少两人分别有 0.3 秒非重叠发言。

- 4,344 条进入待复核，110 条仍满足多人过滤条件。
- 待复核原因：短暂/低占比第二标签 3,061 条，语音过短 1,205 条，
  独立发言证据不足 77 条，旧三人重叠信息不足 1 条。

这是把不确定结果单独保存的策略，不证明 4,344 条都是单人，
也不证明剩余 110 条一定是多人。识别准确率需要逐条人工标签或独立模型复核。
默认不会把待复核条目混入单人输出；用户已明确选择单独输出待复核列表。

可先利用完整状态文件执行 --rebuild-only，无需再次推理。
对短片段若要提高自动判定可靠性，后续应考虑利用原长音频上下文做说话人分离，
再映射回片段，或引入独立声纹模型复核，并单独评估各语言的误剔除与漏检。
